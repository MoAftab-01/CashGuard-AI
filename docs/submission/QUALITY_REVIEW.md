# Submission quality review

| Criterion | Finding | Refinement / remaining work |
|---|---|---|
| Writing quality | The story opens with payment timing, not infrastructure | Keep the problem and user's decision ahead of model/library details; owner must edit in their own voice |
| Side Hustle relevance | Specific audience: freelancers and independent workers | Paid local setup/CSV preparation/support is an explicit unvalidated hypothesis; validate demand after the challenge |
| Creativity | Cash-flow scenarios plus grounded local explanations | Explain why showing an emergency's cash effect is more useful than a generic chatbot answer |
| Technical execution | Existing engines preserved; release tests and real UI/model checks rerun | Use current release report; do not label old holdout replay independent validation |
| Open innovation | Local open-weight inference and inspectable MIT calculations | Distinguish local access controls, separate model terms and hardware costs |
| Gemma integration | Real `gemma3:4b` generation with minimized evidence and fallback | Demonstrate actual inference and show computed evidence separately from prose |
| Demo quality | Real browser recording and fresh synthetic screenshots | Correct negative cash indicator and expanded anomaly explanation; watch final playback and add optional narration |
| Code accessibility | Exact public repository verified; currently empty | Push only after approval, then verify signed out and record the submitted commit |
| Factual accuracy | Matched synthetic baseline and selected model are distinguished | No customers, payments, deployed URL, session URL, hosted CI result or real-world accuracy invented |
| Business value | A private way to inspect cash timing and emergency tradeoffs | Do not claim saved money or validated willingness to pay without real users |

The biggest publication gaps are accessible code, a public/unlisted video URL,
eligibility confirmation and final owner approval—not more application features.
The optional first-user and session sections do not justify fabricated evidence.
